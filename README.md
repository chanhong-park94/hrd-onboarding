# 패스트캠퍼스 천호학원 운영진 온보딩

직업훈련 운영진이 HRD-Net 행정과 심사평가 운영 기준을 익히고, 같은 기준으로 일하도록 돕는 사내 웹사이트입니다. 운영진은 공용 접속 코드, 이름, 개인 PIN으로 들어오고, 관리자는 별도 주소에서 명단·기수·공지를 관리하며 진도를 봅니다. 모든 기록은 기관 구글 시트에 쌓입니다.

| 화면 | 주소 | 누가 |
| --- | --- | --- |
| 운영진 화면 | https://chanhong-park94.github.io/hrd-onboarding/ | 운영진 전원 |
| 관리자 화면 | https://chanhong-park94.github.io/hrd-onboarding/admin.html | 운영 담당자(관리자 코드 필요) |

문항과 가이드는 2026.9.23. 현행 고시(국민내일배움카드 운영규정 제2026-39호, 직업능력개발 훈련품질에 관한 규정 제2026-56호 등) 기준입니다. 고시가 바뀌면 원문이 우선입니다.

## 폴더 구성

| 경로 | 내용 |
| --- | --- |
| `docs/` | 웹사이트 파일. GitHub Pages가 이 폴더를 그대로 공개합니다 |
| `docs/config.js` | 기관 이름, 로고, 진도 저장 주소(API_URL). 가장 자주 고치는 파일 |
| `docs/data.js` | 8단계 핵심 카드와 문항 |
| `docs/guide.js` | 운영 가이드 본문과 자료실 링크 |
| `docs/index.html`, `app.js`, `pages.js` | 운영진 화면 |
| `docs/admin.html`, `admin.js` | 관리자 화면 |
| `docs/style.css` | 두 화면이 함께 쓰는 디자인 |
| `apps-script/Code.gs` | 구글 시트에 붙여 넣는 서버 코드 |

> **주의: 이 저장소는 공개입니다.** 접속 코드나 관리자 코드를 이 저장소의 어떤 파일에도 적지 마세요. 두 코드는 구글 Apps Script의 스크립트 속성에만 둡니다.

## 처음 설정 (한 번만)

### 1. 구글 시트와 서버 코드

1. 구글 드라이브에서 새 스프레드시트를 만듭니다(예: "운영진 온보딩").
2. 시트 메뉴 **확장 프로그램 > Apps Script**를 엽니다.
3. 편집기의 코드를 모두 지우고 이 저장소의 `apps-script/Code.gs` 내용을 붙여 넣은 뒤 저장합니다.

시트 탭(운영진, 진도, 기수, 공지)은 첫 요청 때 자동으로 만들어집니다.

### 2. 접속 코드와 관리자 코드

1. Apps Script 왼쪽 톱니바퀴 **프로젝트 설정 > 스크립트 속성 > 스크립트 속성 추가**.
2. `ACCESS_CODE` = 운영진 공용 접속 코드(8자 이상, 추측하기 어렵게), `ADMIN_CODE` = 관리자 코드(접속 코드와 다르게).
3. **스크립트 속성 저장**.

### 3. 웹 앱으로 배포하고 주소 복사

1. **배포 > 새 배포 > 유형 선택(톱니바퀴) > 웹 앱**.
2. 실행 사용자 **나**, 액세스 권한이 있는 사용자 **모든 사용자**.
3. **배포 > 액세스 승인 > 내 계정 선택**. "Google에서 확인하지 않은 앱" 화면이 나오면 **고급 > (프로젝트 이름)(으)로 이동 > 허용**. 직접 만든 스크립트라서 나오는 안내이며, 이 스크립트는 연결된 시트 하나만 다룹니다.
4. **웹 앱 URL**(`https://script.google.com/macros/s/.../exec`)을 복사합니다. 브라우저에서 열어 "정상 작동 중입니다"가 보이면 성공입니다.

### 4. config.js에 주소 넣기

1. 저장소에서 `docs/config.js`를 열고 연필 아이콘(Edit)을 누릅니다.
2. `API_URL`의 따옴표 안에 3단계 주소를 넣습니다(따옴표와 쉼표는 그대로).
3. **Commit changes**. 1~2분 뒤 반영됩니다(**Actions** 탭의 "pages build and deployment"가 초록 체크면 완료).

`API_URL`이 비어 있으면 운영진 화면은 **미리보기 모드**(코드 없이 입장, 진도는 그 브라우저에만 저장)로 열리고, 관리자 화면은 쓸 수 없습니다.

### 5. 관리자 화면에서 첫 준비

1. 관리자 주소(`.../admin.html`)에서 관리자 코드로 들어갑니다.
2. **기수·일정**에서 첫 기수를 만듭니다(권장 기간 2주).
3. **운영진 명단**에서 운영진 이름을 한 줄에 한 명씩 등록하고 기수를 고릅니다. "명단에 등록된 사람만 입장"은 기본으로 켜져 있어, 명단에 없는 이름은 들어올 수 없습니다.
4. 필요하면 **공지사항**에 첫 공지를 올립니다.

### 6. 운영진에게 안내

- 운영진 화면 주소와 접속 코드를 운영진만 보는 내부 채널에 공지합니다.
- 각자 **명단과 똑같은 이름**과 개인 PIN(숫자 4자리)으로 들어옵니다. 처음 입력한 PIN이 그 사람의 PIN이며, 같은 이름과 PIN이면 다른 기기에서도 이어집니다.
- 공용 PC에서는 **내 정보 > 로그아웃**.

## 자주 하는 관리

| 상황 | 할 일 |
| --- | --- |
| 새 운영진 입사 | 관리자 화면 > 운영진 명단에서 등록하고 기수 배정 |
| 퇴사 | 운영진 명단에서 **퇴사 처리**(입장 차단, 기록은 보존). 접속 코드가 외부로 샜다면 스크립트 속성의 `ACCESS_CODE`도 바꾸고 새 코드를 공지 |
| PIN을 잊음 | 운영진 명단에서 **PIN 초기화**. 그 사람이 다음에 직접 입장할 때 입력한 PIN이 새 PIN이 되고, 예전 기기의 자동 로그인은 풀립니다 |
| 공지·일정 | 관리자 화면의 공지사항, 기수·일정에서 바로 수정 |
| 기관 이름·로고 | 로고는 **Add file > Upload files**로 `docs/`에 `logo.png`를 올리고 `docs/config.js`의 `ORG_LOGO`를 `"logo.png"`로 |
| 문항·가이드 수정 | `docs/data.js`(문항), `docs/guide.js`(가이드·자료실). 형식이 까다로우니 Claude에게 수정본을 요청하는 것을 권합니다 |
| `Code.gs`가 바뀜 | Apps Script에 새 내용을 붙여 넣고 **배포 > 배포 관리 > 연필 > 버전: 새 버전 > 배포**. 주소는 그대로입니다 |
| 예전 상태로 되돌리기 | 저장소의 **Commits** 기록에서 이전 버전을 확인하고 되돌릴 수 있습니다 |

## 알아 둘 점

- 접속 코드·관리자 코드·명단은 구글 쪽 서버에서 확인하므로, 코드와 명단 없이는 진도 저장과 관리 기능을 쓸 수 없습니다. 다만 문항과 가이드는 공개 저장소와 사이트 파일에 들어 있어 누구나 볼 수 있습니다(공개된 규정 내용입니다).
- 업무 도구의 날짜 계산은 고시대로 달력 날짜로 세고 토·일만 표시합니다. 공휴일은 반영하지 않으니 HRD-Net에 표시된 날짜를 우선합니다. 장려금 계산기도 참고용이며 실제 금액은 고용센터 산정이 기준입니다.
- 사이트는 검색엔진에 나오지 않도록 `noindex`가 설정돼 있습니다.
- GitHub Pages 한도: 사이트 1GB, 월 전송량 100GB(권장 한도), 시간당 배포 10회(권장 한도).
