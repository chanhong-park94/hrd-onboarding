# 운영진 온보딩 챌린지

직업훈련기관 운영진이 HRD-Net 행정과 심사평가 운영 기준을 8단계 116문항으로 익히는 사내 온보딩 웹사이트입니다. 운영진은 공용 접속 코드, 이름, 개인 PIN으로 들어오고, 진도는 기관 구글 시트에 쌓입니다.

- 사이트 주소: https://chanhong-park94.github.io/hrd-onboarding/
- 문항 기준일: 2026.9.23. 현행 고시(국민내일배움카드 운영규정 제2026-39호, 직업능력개발 훈련품질에 관한 규정 제2026-56호 등). 고시가 바뀌면 원문이 우선입니다.

## 폴더 구성

| 경로 | 내용 |
| --- | --- |
| `docs/` | 웹사이트 파일. GitHub Pages가 이 폴더를 그대로 공개합니다. |
| `docs/config.js` | 기관 이름, 로고, 진도 저장 주소(API_URL). 가장 자주 고치는 파일입니다. |
| `docs/data.js` | 8단계 핵심 카드와 문항 |
| `docs/app.js`, `docs/index.html` | 화면과 동작 |
| `apps-script/Code.gs` | 구글 시트에 붙여 넣는 진도 저장 코드 |

> **주의: 이 저장소는 공개입니다.** 접속 코드나 관리자 코드를 이 저장소의 어떤 파일에도 적지 마세요. 두 코드는 구글 Apps Script의 스크립트 속성에만 둡니다.

## 처음 설정 (한 번만)

### 1. 진도를 모을 구글 시트 만들기

1. 구글 드라이브에서 새 스프레드시트를 만듭니다(예: "운영진 온보딩 진도").
2. 시트 메뉴 **확장 프로그램 > Apps Script**를 엽니다.
3. 편집기의 코드를 모두 지우고 이 저장소의 `apps-script/Code.gs` 내용을 붙여 넣은 뒤 저장합니다.

### 2. 접속 코드와 관리자 코드 정하기

1. Apps Script 왼쪽 톱니바퀴 **프로젝트 설정 > 스크립트 속성 > 스크립트 속성 추가**.
2. `ACCESS_CODE` = 운영진 공용 접속 코드(8자 이상, 추측하기 어렵게), `ADMIN_CODE` = 관리자 화면 코드(접속 코드와 다르게).
3. **스크립트 속성 저장**.

### 3. 웹 앱으로 배포하고 주소 복사하기

1. **배포 > 새 배포 > 유형 선택(톱니바퀴) > 웹 앱**.
2. 실행 사용자 **나**, 액세스 권한이 있는 사용자 **모든 사용자**.
3. **배포 > 액세스 승인 > 내 계정 선택**. "Google에서 확인하지 않은 앱" 화면이 나오면 **고급 > (프로젝트 이름)(으)로 이동 > 허용**. 직접 만든 스크립트라서 나오는 안내이며, 이 스크립트는 연결된 시트 하나만 다룹니다.
4. 나온 **웹 앱 URL**(`https://script.google.com/macros/s/.../exec`)을 복사합니다.
5. 그 주소를 브라우저에서 열어 "정상 작동 중입니다"가 보이면 성공입니다.

### 4. GitHub에서 config.js 고치기

1. 이 저장소에서 `docs/config.js`를 열고 오른쪽 위 연필 아이콘(Edit)을 누릅니다.
2. `ORG_NAME`에 기관 이름, `API_URL`의 따옴표 안에 3단계 주소를 넣습니다. 따옴표와 쉼표는 그대로 둡니다.
3. **Commit changes**를 누릅니다. 1~2분 뒤 사이트에 반영됩니다(**Actions** 탭의 "pages build and deployment"가 초록 체크가 되면 완료).

`API_URL`이 비어 있으면 사이트는 **미리보기 모드**(코드 없이 입장, 진도는 그 브라우저에만 저장)로 열립니다.

### 5. 운영진에게 안내하기

- 사이트 주소와 접속 코드를 운영진만 보는 내부 채널에 공지합니다.
- 각자 이름과 개인 PIN(숫자 4자리)으로 들어옵니다. 처음 입력한 PIN이 그 사람의 PIN이며, 같은 이름과 PIN이면 다른 기기에서도 이어집니다.
- 공용 PC에서는 **내 정보 > 로그아웃**.

## 관리자 화면

입장 화면 오른쪽 아래 **관리자 화면**에서 `ADMIN_CODE`를 넣으면 운영진별 단계 점수, 최종 심사 합격 여부, 마지막 학습 시각이 표로 나옵니다. 같은 내용이 구글 시트의 `진도` 탭에 쌓입니다.

## 자주 하는 관리

| 상황 | 할 일 |
| --- | --- |
| 퇴사자가 생김 | Apps Script 스크립트 속성의 `ACCESS_CODE`를 새 코드로 바꾸고 운영진에게 공지. 즉시 적용되며 재배포가 필요 없습니다. |
| PIN을 잊음 | 시트의 숨긴 B열(PIN 확인값)에서 그 사람 칸을 지움. 다음 입장 때 새 PIN을 정합니다. |
| 기관 이름·로고 변경 | 로고는 **Add file > Upload files**로 `docs/`에 `logo.png`를 올리고, `docs/config.js`의 `ORG_LOGO`를 `"logo.png"`로 바꿉니다. |
| 문항 수정·추가 | `docs/data.js`를 고칩니다. 형식이 까다로우니 Claude에게 수정본을 요청하는 것을 권합니다. |
| `Code.gs` 수정 | 저장소 파일을 고친 뒤 Apps Script에도 붙여 넣고 **배포 > 배포 관리 > 연필 > 버전: 새 버전 > 배포**. 주소는 그대로입니다. |
| 예전 상태로 되돌리기 | 저장소의 **Commits** 기록에서 이전 버전을 확인하고 되돌릴 수 있습니다. |

## 알아 둘 점

- 접속 코드는 구글 쪽 서버에서 확인하므로 코드 없이는 진도 저장과 관리자 화면을 쓸 수 없습니다. 다만 문항은 공개 저장소와 사이트 파일에 들어 있어 누구나 볼 수 있습니다(공개된 규정 내용입니다).
- 사이트는 검색엔진에 나오지 않도록 `noindex`가 설정돼 있습니다.
- GitHub Pages 한도: 사이트 1GB, 월 전송량 100GB(권장 한도), 시간당 배포 10회(권장 한도). 운영진 온보딩 용도로는 충분합니다.
